# PR32 — OCR 自动动作与 AI 回答自动朗读快捷开关

基线：已合并 PR31 的 `main`，`fe0a80a`。验证日期：2026-10-16。

## 实际修改与使用

- 主设置 OCR 区域新增互斥动作：仅显示结果（默认）、自动朗读、自动问 AI；点击保存设置后用于下一次主动框选。新增 `OcrAction`，旧 JSON 缺少字段时为 `ShowResult = 0`。
- OCR 自动问 AI 使用独立的 `AllowOcrLlm` / `OcrLlmAuthorizedBaseUrl`，默认关闭，绑定 `Settings.NormalizeServiceUrl` 规范化后的 LLM 地址。先保存地址，再在 OCR 区域明确授权；更换地址清除授权。界面显示目标和可能收费的说明。普通 Auto Ask 开关、应用规则、鼠标上传授权不授权 OCR，也不会被 OCR 开启。
- OCR 正常完成后先显示结果；等 `TextCaptureOperation.RunAsync` 结束并恢复截图前隐藏窗口后，才调度一次后续动作。原文与动作使用本次 OCR 的已保存快照；编辑后的文字继续供手动按钮使用，不自动复制。
- 每次 OCR 的后续动作有独立取消生命周期及一次执行保护。新 OCR、Stop、退出和更新的手动任务阻止旧的待启动动作／待合成结果回流。空白、失败、取消及被替换回调不触发动作。设置或授权改变会阻止尚未启动的旧动作；只切换 `LlmAutoRead` 不使 OCR 失效，新问答使用切换后的值。
- 自动朗读先在工作线程检查当前 Provider 自动上传授权、文本、凭据、语音、MiMo 参数与输出条件，再调用原有 `ReadingSession` 自动入口。复用原有物理／虚拟输出、风格、暂停、继续、Stop；已知无效条件不会先停止原播放。远程请求或设备运行中仍可能失败，沿用原有错误反馈，不自动重试。
- `QuestionSource` 区分手动、鼠标自动和 OCR 自动问答，复用 `QuestionSession` 执行、逐句队列及取消机制。OCR 自动回答窗口不主动激活；在线 TTS 未获对应自动授权时只显示回答，仍允许主动重新朗读。
- AI 回答窗口新增「自动朗读 AI 回答」，与主设置共用 `LlmAutoRead`，两处点击均立即持久化、双向同步。单字段保存路径不取消当前任务，也不刷新其他草稿控件；保存失败保留原设置并恢复勾选。已启动问答保留启动快照，手动朗读按钮不受开关关闭限制。
- README 已同步。未改变 CLI/MCP 协议、发布结构或第三方驱动边界。
