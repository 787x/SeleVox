# PR13 — 音频工作台 AI 辅助创作

日期：2026-10-14。基线：`origin/main` / `e0ba4db`（PR12 已合并）。Windows x64、.NET 10、WPF。

## 实际修改

- 三个标题右侧增加“AI 生成”，MiMo 音频标签脚本工具栏增加“AI 添加标签”。按钮显示生成中状态；正文下提供费用 / 发送提示、取消及恢复最近一次替换前文本。标题使用右侧 Dock 与可换行标题，左侧继续滚动。
- 复用主设置的 LLM URL、Model、地址隔离的 Credential Manager Key、Thinking 与 Streaming。专用 System Prompt 仅存在请求快照中，不更改日常问答设置。VoiceDesign 使用附件的八维提示词及示例，补充 user 输入位置和 1000 字符限制。附件自身“不输出标点”与逗号分句、示例含标点存在矛盾，保留原规则，不宣称模型一定严格满足所有措辞。
- 风格只生成自然语言指导；正文按当前 Provider / 预置 MiMo 模式 / 控制方式快照判断播报稿或歌词。VoiceDesign / VoiceClone 不自动视为唱歌。
- 每个工作台一个有效 AI 操作，独立于 TTS / 问答会话。开始时冻结配置和输入；输入编辑（保守地包括三个目标框任一编辑）、Provider / 模型模式 / 控制方式切换、新操作、取消和关闭均撤销旧代次。非协作迟到结果不能写回。
- 只应用 ChatCompletionClient 正常完成的返回值，不显示或应用部分 SSE。空回答、控制字符、代码围栏、输出超限及服务失败保留原文。1000 / 32768 UTF-16 字符上限不静默截断。
- 标签校验按原文与输出依次匹配，仅允许跳过合法完整新增标签；已有括号表达式作为整体匹配，不允许在其内部添加标签。重复同名标签、现有标签、原文标点与 CRLF 均保留。校验线性扫描且在后台执行，可取消，不退化为改写。
- 成功替换走原 TextChanged / 预览 / 草稿状态；恢复操作恢复最近一次替换前内容并覆盖该框此后的编辑。恢复记录仅在窗口内存中，关闭清理。AI 逻辑不调用音频生成、播放、停止或结果清理。

## Unicode 标签插入边界修复（2026-10-14）

仅修复 `CreativeText.OnlyInsertsTags()` 的新增标签位置校验，不扩展创作功能、UI 或网络协议。原文仍按 UTF-16 序列逐字保留；使用 .NET 10 `StringInfo.ParseCombiningCharacters` 建立原文 Unicode 文本元素边界表，仅在边界位置允许跳过合法新增标签，并显式禁止 CR / LF 之间插入。

完整方括号表达式仍作为不可拆分单元。若闭括号后有附着的组合字符，则将匹配单元延伸到该文本元素结束；这样既保护闭括号与组合字符，也允许在整个原表达式之前插入重复同名标签。相同标签有等价插入解释时，只要存在合法的原文保留解释即可接受，不要求识别相同标签实例的身份。

实际验证：

- 先运行新增测试复现旧代码错误：emoji 代理项内部插入标签被接受，定向组 1 失败、14 通过（`pr13-unicode-before.trx`）。修复过程中边界用例也发现重复标签与闭括号附着组合字符的匹配问题，已通过延伸原表达式匹配单元修复。
- 最终相关组 **70 通过、0 失败、0 跳过**，`TestResults/pr13-unicode-final.trx`。包括 CreativeText / CreativeWindow、DirectorText / DirectorWindow 和 MiMoCreative / MiMoCreativeWindow。
- 新增两个定向测试：对固定 emoji 代理项、多个组合字符、CRLF、ZWJ emoji、肤色修饰符、旗帜、中文正常文本、完整 / 未闭合方括号及闭括号附着组合字符，在每个 UTF-16 位置逐一尝试插入全部 11 种合法标签（连续重复两次），校验仅允许正确边界；同时覆盖混合文本多处正常插入、重复现有标签、原文未改、Unicode 规范化改写拒绝及 CRLF 改 LF 拒绝。
- Release 构建：**0 警告、0 错误**。`git diff --check` 通过。
- 本次未调用真实 LLM 或 TTS，未新增人工界面 / 听音验证，也未发布新的便携目录；原有 WPF 相关自动回归已执行通过。此修复的验收依据为定向逻辑与相关自动回归，不将此前人工通过反馈扩展为本次 Unicode 修复的人工实测。
