# PR17 — 内置虚拟麦克风集成

日期：2026-10-14。基线 `db52986`，PR16 已合并后的最新 `origin/main`。Windows 11 x64（build 26300）、.NET 10、NAudio 3.1.0；实际测试进程未提权（Administrator token=False）。

## 实际实现

- 复用普通 VB-CABLE，未开发内核驱动、混音器或常驻音频服务。枚举 Render / Capture 的全部状态，通过 Configuration Manager 追溯共同 `ROOT\VBAUDIOVACWDM` PnP 驱动 devnode；名字只用于显示。保存完整 Render / Capture ID、驱动实例及录音验证状态；重命名不会按名字改路由，消失的 ID 保留，多个 pin 要求手选并录音验证。
- 主设置独立开关默认关闭，提供扫描、选择、状态、固定 PCM 录音验证及官方安装引导。设置可见时每 2 秒重扫，隐藏 / 关闭后停止定时扫描；每次实际播放另行检查配对及活跃状态。不能准确判断重启必要性时仅提示检查，不宣称已创建麦克风。
- 普通 WAVE、流式 24 kHz PCM、工作台试听和 LLM 逐句使用现有播放工厂；保留 Shared Mode、重采样、独立 reader、音量和起音补偿。虚拟输出追加并按真实 endpoint ID 去重；指定虚拟目标不会回退到扬声器。物理目标保持原有回退规则。虚拟异常隔离由已有 MultiOutputPlayback 管理。
- 关闭 / 更换已启用路由并保存立即 Stop 当前前台任务，后续普通朗读排除此虚拟端点，不删除物理设置。仅虚拟目标且关闭时明确拒绝播放。CLI/MCP 显式 `devices` 独立严格覆盖（包括默认值、预设、空数组及 null），无字段才继承主虚拟路由。旧 Agent 在未启用虚拟功能时保留严格输出行为。文件导出、TTS 服务检测不打开播放器。
- 测试只读取选定虚拟 Capture，不读取物理麦克风；3 秒固定频率序列 PCM 加短静音，归一化互相关须 ≥0.6，失败不能启用。录音在内存、有限预算及大小限制，取消 / Stop / 新朗读 / 隐藏窗口释放。共享线不保证来源隔离，也不更改默认麦克风。

真实 Windows Capture 验证：

- 实际发现两个活跃 Render：`CABLE In 16 Ch (VB-Audio Virtual Cable)`、`扬声器 (VB-Audio Virtual Cable)`；Capture 为 `CABLE Output (VB-Audio Virtual Cable)`，共同 PnP 驱动身份匹配。对两个 Render 分别播放 24 kHz / PCM16 / mono 固定 3 秒序列，从 **Capture 端录音**，最终波形关联分别为 `0.9105`、`0.9981`；这不是 Render loopback 或音量表检测。
- Realtek 物理扬声器 + 虚拟 Render 双路：实际 Capture 在播放、继续和新朗读替换时 RMS 非零，在 Pause、Stop、关闭后物理独播时静音。流式 24 kHz PCM 同样实测双路及 Pause / Resume / Stop。验证会话和非残留注入，不声称声学同步或耳机人工听音。
- 独立第三方 FFmpeg DirectShow 实际选择该 Capture，录得约 `4.98–4.99` 秒有效 WAV，固定波形关联约 `0.9105–0.9833`；不是 Discord / OBS 界面验收。文件仅含固定测试 PCM，测试后删除。
- WPF 实际创建 / 显示主窗口，通过按钮处理链手选、真实录音验证、启用、保存、关闭及 ID 保留；截图检查 `artifacts/pr17-ui/pr17-virtual-microphone.png`。这是程序化桌面验证，不称为人工鼠标验收。
- 受控 LLM 最终回答逐句进入实际 ReadingSession / 双路 WASAPI，真实 Capture 收到两段固定 PCM，完成后无残留；没有调用真实 LLM 或付费 TTS。MiMo 以其既有流式工厂输入固定 PCM，SSE / 取消由定向回归覆盖，没有真实在线 MiMo 请求。

发布 CLI / MCP 的真实测试将主配置临时设为本地 Windows TTS + 双路、临时清空 Agent 默认设备，结束后原样恢复两个文件，仅结束测试自己启动的后台实例。涵盖缺省朗读真实 Capture、显式物理覆盖时 Capture 静音、MCP stdio 朗读及 Stop、文件生成无注入。最终专项通过；测试先等待真实 Job=playing 再取 Capture 样本，未将早期用错 CLI JSON 参数及过早读取样本的失败尝试记作通过。

## 未验证与限制

以下清单描述代理执行的验证边界；用户后续的六项人工验收反馈见文末，二者分别记录。

- 没有首次安装、升级、拒绝 UAC、需要重启状态的实际安装测试；审计签名及许可不等于安装端到端通过。应用不提供自动安装能力。
- 没有实际禁用 / 卸载共享驱动、拔掉用户设备、重启或休眠唤醒；对应不可用 / ID 变化 / 异常隔离以受控测试覆盖，仍需实机验收。实际设备重命名未执行，名字独立性用模拟重命名覆盖。
- 当前耳机不可用；实测物理端为 Realtek 扬声器。Discord / OBS / Zoom UI、真实 MiMo / LLM / Azure / Edge / OpenAI 在线播放、VoiceDesign / Clone 服务未新增端到端验收，工厂共享不能替代每项人工确认。
- 仅普通 VB-CABLE PnP 身份进入虚拟选择列表，其他驱动不以相似名字宣称兼容；同驱动多个 pin 仍须录音验证。历史验证标志不是长期保证，设备重新安装生成新 ID 后不会自动改配对。
- Capture 可被其他应用共享，声音可能包括它们主动路由的内容。SeleVox 没有采集系统声音 / 物理麦克风或提供独占来源隔离。Windows 隐私权限、独占占用和第三方降噪 / 门限仍可能阻止实际目标应用接收。
